# Google Workspace integrations: current state

Checked 25 October 2026. **Planning only; implementation requires approval.** This folder contains the entire deliverable; application code, migrations, infrastructure and existing staged work were not changed. Paths below are relative to the workspace root. The active repositories are `backend/` and `frontend/`; `techsync-crm-v2/` is an older copy.

## Recommendation and reading order

Build a shared Google connection **service and UI**, with separate credential grant profiles for existing Gmail and new Workspace features. Keep `GmailAccount` compatible; it is the foundation API's logical EmailAccount, not a missing table to recreate. Start with the shared foundation and opt-in Calendar scheduling. Deliver Drive Picker attachment links and Sheets export next; they can launch ahead of Calendar if its verification is delayed. Add linked-event two-way Calendar sync and directional Sheets automations after the simpler flows are proven. Keep pg-boss; Redis is unnecessary for this design.

Read [Google requirements](02-google-requirements.md), [market and feature decisions](03-market-and-use-cases.md), [architecture](04-architecture.md), [UX](05-ux-flows.md), [roadmap](06-roadmap.md), [compliance](07-compliance-and-verification.md), [QA](08-test-and-qa-plan.md) and [decisions](09-decision-log.md). Ready-to-run future implementation prompts are in [10-implementation-prompts](10-implementation-prompts/00-foundation.md).

## Important boundaries

- Existing Gmail/Templates work is staged in both repositories. It remains user-owned; review it before later implementation, preserve its index and routes, and do not fold it into an unrelated commit.
- Google Cloud project IDs, OAuth publishing/verification state, real redirect configuration, quota grandfathering, KMS operation, tenant contracts and external storage operation were not accessed or assumed.
- No application, schema, `.env`, deployment or production database changes are authorized in this task. The [decision log](09-decision-log.md) records unresolved inputs without blocking delivery of this plan.
